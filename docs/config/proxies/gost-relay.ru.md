# GOST Relay

```{.yaml linenums="1"}
proxies:
  - name: "gost-relay-hop"
    type: gost-relay
    server: relay.example.com
    port: 443
    udp: true
    tls: true
    # mux: true
    # ws: true
    # ws-opts:
    #   path: /ws
    #   headers:
    #     Host: relay.example.com
    # sni: relay.example.com
    # username: user
    # password: pass
    # client-fingerprint: chrome
    # fingerprint: xxxx
    # certificate: ./client.crt
    # private-key: ./client.key
    # skip-cert-verify: true
    # name-cert-verify: example.com
    # dialer-proxy: "ss1"
    # interface-name: "WLAN"
    # routing-mark: 6666
    # ip-version: ipv4-prefer
```

!!! note
    GOST Relay используется для передачи других прокси (таких как ss/vmess/vless/trojan) через сервер GOST relay. Укажите его как `dialer-proxy` для прокси верхнего уровня — тогда соединения и UDP-трафик этого прокси будут проходить через ретранслятор.

    Поддерживаются два режима:

    * **Динамический режим** (по умолчанию, `forward: false`): ретранслятор подключается к целевому адресу, запрошенному прокси верхнего уровня. В этом режиме `server` прокси верхнего уровня обычно указывает адрес, доступный со стороны ретранслятора (например `127.0.0.1` на сервере ретранслятора).
    * **Режим пересылки** (`forward: true`): сервер ретранслятора подключается к настроенной им цели; адрес прокси верхнего уровня используется только для получения потока от ретранслятора.

    Как и другие типы прокси, GOST Relay начинает подключение только тогда, когда трафик направляется на узел с помощью правил, групп политик или других методов маршрутизации.

[Общие поля](./index.md)

## name

Обязательно, имя прокси. Не должно повторяться.

## type

Обязательно, фиксированное значение `gost-relay`.

## server

Обязательно, адрес сервера GOST relay.

## port

Обязательно, порт сервера GOST relay, в диапазоне 1–65535.

## forward

Опционально, использовать ли режим пересылки. Значение по умолчанию — `false` (динамический режим).

* `false` (динамический режим): ретранслятор подключается к целевому адресу, запрошенному прокси верхнего уровня; используется вместе с `dialer-proxy` для передачи других исходящих прокси.
* `true` (режим пересылки): сервер ретранслятора подключается к настроенной цели; адрес прокси верхнего уровня используется только для запроса потока от ретранслятора.

## udp

Опционально, включить ли UDP. Значение по умолчанию — `false`.

## ws

Опционально, включить ли транспорт WebSocket. Значение по умолчанию — `false`.

В сочетании с `tls` и `mux` образует несколько видов ретрансляции:

* `ws` + `tls`: `relay+wss`
* `ws` + `mux`: `relay+mws`
* `ws` + `tls` + `mux`: `relay+mwss`

## ws-opts

Опционально, параметры транспорта WebSocket.

### path

Опционально, путь WebSocket. Значение GOST по умолчанию — `/ws`; должно совпадать с `ws.path` слушателя ретранслятора.

### headers

Опционально, заголовки запроса WebSocket в виде пар ключ-значение (строки). Часто используется для задания заголовка `Host`, например `Host: relay.example.com`.

```{.yaml linenums="1"}
ws-opts:
  path: /ws
  headers:
    Host: relay.example.com
```

## tls

Опционально, включить ли TLS. Значение по умолчанию — `false`.

## mux

Опционально, включить ли мультиплексирование (smux). Значение по умолчанию — `false`. При включённом `tls` и отключённом `ws` выбирает `relay+mtls`.

## sni

Опционально, TLS SNI. По умолчанию берётся `Host` из `ws-opts.headers`, затем `server`.

## username

Опционально, имя пользователя для аутентификации на ретрансляторе.

## password

Опционально, пароль для аутентификации на ретрансляторе.

## skip-cert-verify

Опционально, пропускать ли проверку сертификата сервера. Значение по умолчанию — `false`.

## name-cert-verify

Опционально, изменяет только цель проверки DNSName сертификата, не SNI.

## fingerprint

Опционально, SHA256-отпечаток сертификата сервера, используемый для его проверки.

## certificate

Опционально, путь к файлу клиентского сертификата, используется для mTLS.

## private-key

Опционально, путь к файлу закрытого ключа клиента, используется для mTLS.

## client-fingerprint

Опционально, отпечаток клиентского TLS (например `chrome`).

## dialer-proxy

Опционально, идентификатор исходящего прокси, через который устанавливается соединение с GOST relay; `ss1` — имя другого узла прокси.

В динамическом режиме использование GOST Relay в качестве `dialer-proxy` для прокси верхнего уровня позволяет последнему (ss/vmess/vless/trojan и др.) передавать свой трафик через ретранслятор.

## interface-name

Опционально, указать исходящий сетевой интерфейс.

## routing-mark

Опционально, настроить fwmark в Linux.

## ip-version

Опционально, указать версию IP для исходящих соединений.

Возможные значения: `dual`/`ipv4`/`ipv6`/`ipv4-prefer`/`ipv6-prefer`.
